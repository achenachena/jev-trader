# 当前目标与 paper bot V1

更新：2026-09-24。只读 SSE 实时网页已加入，见 [观察台与部署](DASHBOARD_DEPLOY.zh-CN.md)。

用户的最终目标是能够自动在 Polymarket 开仓、平仓的 bot；
当前目标是用虚拟资金在真实数据上运行同样的流程，验证策略。本文件取代
旧的“停在离线阅读测试”决定。工程验收和盈利验证分开，离线题目分数不再
阻止 paper 实验。最终实盘执行器尚未实现，也没有获得当前真钱交易授权。

## 已实现的最小闭环

```text
官方 RSS/Atom 新条目或内容修订
  → 记录首次收到时间、发布时间、原有版本
  → 配置的关键词匹配已审核合约
  → 简单规则 / Jev 判断（独立虚拟账户）
  → 方向、相关性、清晰度、资金和盘口筛选
  → 固定限价与最早到达时间
  → 到达后重新读取状态、费率、真实盘口
  → 本地模拟买入、持仓、卖出、现金与费用
  → SQLite 持久化、报告、重启恢复
```

没有钱包、私钥或真实下单接口。唯一带密钥的请求发往 Vercel Jev，
Polymarket 和官方新闻源仅使用公开 GET。未来可以增加独立的真实执行器，
但不能通过改一个 mode 值把当前程序变成实盘。

## 固定的策略假设

**官方产品消息出现后，价格可能仍继续向消息支持的方向调整。** Jev 判断
相关性、证据/规则清晰度及 SUPPORTS_YES / SUPPORTS_NO / NO_SIGNAL。
不要求结算结果已经确定，未来计划也可能提供方向证据。分类概率不是最终
结果概率，不使用它计算 Kelly 仓位或假装得到“公允价格”。

首批名单是 8 个活跃二元合约，分成折叠 iPhone、触屏 MacBook、Vision Pro、
GTA 发布/延期 4 个风险组。来源是 Apple Newsroom 和 Take-Two 官方 RSS。
同组多个到期日不是独立机会，每账户每组最多一笔风险；配置顺序固定，
先满足条件的合约会占用该组额度。名单不是自动扩张，规则哈希改变会停止
新开仓。初始规则/源映射由本项目建立，用户不用手工整理每条新闻。

这是一个**机会可能稀少**的窄策略，不是日内刷单策略。只有新消息才判断；
无事件、没有通过盘口条件、最终零交易，都是有效结果。

## 初始参数（实验假设，不是经过收益优化的参数）

| 参数 | V1 |
| --- | --- |
| 账户 | rules / jev 各虚拟 $1,000，不能合并收益 |
| 每笔预算 | 含买入费用最多 $10 |
| 账户总成本和待成交买单预算 | 最多 $100 |
| 累计净值下界回撤暂停开仓 | $50；保留退出能力 |
| Jev 筛选 | 相关性 ≥0.90、清晰度 ≥0.80、所选方向 ≥0.80 |
| 可开仓价格 | 0.05–0.95 |
| 最大价差 | 每份 0.03 |
| 顶档估计往返摩擦 | 买价的 8% 以内；不是预期收益估计 |
| 深度 | 仅采用可见深度的 50% |
| 限价保护 | 信号时最优价 ±2 ticks |
| 最早模拟到达 | 下单决定后 2 秒，实际轮询/网络可能更晚 |
| 订单过期 | 60 秒，重启后不补填过期订单 |
| 退出 | 可完整清算收益 ≥15%、损失 ≥10%、持有 4 小时，或反向证据 |
| 同风险组冷却 | 24 小时 |
| 新闻 / 元数据 / 持仓盘口轮询 | 60 秒 / 60 秒 / 15 秒 |
| 消息时效 | 源更新/发布时间距接收不超过 1 小时；未知时刻跳过 |
| Jev 调用限制 | 每 UTC 日 24 次、该数据库总计 200 次，失败也占次数 |

止损和止盈是卖出意图的触发条件，不保证在该价格成交。退出没有足够深度
只部分卖出；没有买盘继续保留库存。小于最小订单量的残余视为不可出售 dust，
不凭空清零。费用为每档 `shares × rate × p × (1-p)`，按微美元向上取整，
现金等值扣除；这是保守 paper 近似，不声称精确复现真实撮合的份额舍入。
只支持返回明确 `fd.e=1`、`fd.to=true` 的费用配置，未知曲线不模拟交易。

Jev 调用次数是硬限制，不是美元硬预算。成功费用从接口记录，缺失/失败
费用为未知，不当零。当前运行成本与交易 PnL 分开列出；没有充值或自动充值。

## 模拟的真实性与边界

- 先保存决定，再等到实际到达时抓盘口；不能使用未来价格倒填过去。
- 买入扫卖盘、卖出扫买盘，按价格排序与逐档深度计算；价差已体现在成交中，
  不重复扣除。没有 maker 排队模拟，没有用买入相反 token 假装平仓。
- 同账户、同 token、同一侧未变化的深度不能重复使用；规则/Jev 是独立
  反事实账户，可分别使用同一市场深度。不同快照并不保证真实可成交；
  仍无法模拟并发撤单、撮合优先级与隐藏流动性。
- 盘口健康依据新鲜 HTTP 接收、请求耗时、token 对应和未交叉检查；市场
  更新时间可能很旧，所以保留源 timestamp，不把安静市场误判成断线。
- 初次启动只为源建立基线，旧 30 条新闻不会触发交易。后续版本按 URL+内容
  去重。崩溃中断的证据跳过并记录，不重新赋予早已失去的机会。
- 账本使用 Decimal 和 SQLite 事务，现金、份额、逐档成交与深度消耗一起提交。
  同一数据库只能运行一个进程；参数或实现代码变更需要新数据库，保存实现哈希。
- 新闻输入目前是官方 RSS 标题和摘要，**不含完整文章**。摘要缺失关键事实
  会漏掉机会；没有通用网页抓取或秒级消息源。60 秒轮询无法竞争几秒内消失
  的优势，这个限制必须计入策略结论。
- 无自动结算/赎回模拟：市场关闭而库存未卖出时进入不可交易/待处理状态，
  不按页面价格猜测 payout。报告保留库存并给保守估值下界；这类结果不能
  当已实现亏损。V1 的主路径是到期前短持有卖出。
  开仓还要求元数据截止时间至少留出完整持有窗口加一分钟，但市场可能提前关闭。
- 两个策略臂共享单个轮询进程，模型请求期间可能拖慢整个循环。保存真实
  决策和到达时间，不假设固定两秒成交；收益对照不等同于独立并行部署的
  延迟对照。慢请求可能导致订单过期，而不是事后补成交。
- 首版没有通用模型第三账户、历史最优参数搜索、复杂前端、消息推送、全市场
  扫描或 VPS 部署。Dockerfile 已提供，但未以 Docker 实测部署。

## 如何运行和看结果

Python 3.10+，macOS/Linux，只有标准库。仓库根目录执行：

```sh
python3 -m jev_trader doctor
python3 -m jev_trader run
```

它持续运行至 Ctrl+C；不会因为关闭笔记本而自动迁移到云端。不要同时启动
两个使用同一数据库的进程。修改 config/paper.json 后必须使用新的 `--db`。
只读取 `.env` 的 `AI_GATEWAY_API_KEY` 或同名环境变量，不执行环境文件。

```sh
python3 -m jev_trader report
python3 -m unittest discover -s tests -v
python3 -m jev_trader demo --output reports/my-demo
```

运行数据：`data/paper.sqlite`；报告：`reports/paper/latest.md` 与 `latest.json`。
报告显示 UTC 更新时刻、现金、已实现、未实现下界、库存、未估值份额、来源
错误和模型费用。UTC 日变化注明实际起点，初次运行日为部分日期；缺失估值
不得冒充完整日收益。静态报告不会在进程停止后自动更新。

demo 完全使用合成行情和模拟 Jev 回答，测试两个账户自动开平仓。它的
正收益仅由测试数据构造，**不是策略回测或实盘 paper 收益**。

仅运行原来的 paper worker 可使用如下命令。包含网页的推荐部署方式见 [观察台与部署](DASHBOARD_DEPLOY.zh-CN.md)。此交付未启动云端服务：

```sh
docker build -t jev-trader .
docker run --name jev-paper --restart unless-stopped --env-file .env \
  -v "$PWD/data:/app/data" -v "$PWD/reports:/app/reports" jev-trader python -m jev_trader run
```

## 验证与后续判断

当前验收：离线测试、合成闭环、实际公共数据 doctor、Jev 新格式连接、
真实数据短时冒烟。没有达到 24 小时稳定性验证，更没有长期收益证据。

观察 7–14 个有效运行日作为首次检查点，不作为盈利证明或自动升级期限。
分析候选消息数、弃权与拒绝原因、实际成交机会数、持仓/已实现净收益、
按事件分组的盈亏、模型成本、数据缺口，以及 Jev 相对规则的变化。
若只有少数公告，结论就是样本不足；不得降低门槛制造成交。

真实交易阶段还需要官方签名订单适配器、真实部分成交/撤单对账、费用/份额
精度校准、结算处理以及小额执行验证；必须在新的明确授权下启用。
