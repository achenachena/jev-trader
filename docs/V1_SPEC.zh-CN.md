# Jev × Polymarket：最终小型 V1 方案

> Historical larger design. Current implemented scope: [Paper V1](PAPER_V1.zh-CN.md). In particular, raw Jev probability pricing and the three-arm design below are not implemented.

日期：2026-09-24。状态：设计已收敛，尚未实现、未运行模型实验、未取得盈利证据。

## 1. 决策与目标

做一个可持续运行、每天查看盈亏、可复现的影子交易研究系统。V1 不连接钱包、不实现真实下单。用户总本金预算为 $1,000；V1 使用虚拟资金，运行成本单独核算。

核心问题：收到新的一手证据以后，Jev 能否正确解释合约条件，并提供超过简单规则的、在真实盘口上仍可执行的价值？

技术上可实现；策略收益未知。7–14 天是检查点，不是盈利证明或自动升级期限。没有交易、样本不足、Jev 无增益均为有效研究结果。

## 2. 严格控制范围

首选市场领域：产品发布／公众可用性事件。理由是官方发布源与“宣布、预告、内测、开放购买”等语义差别便于复核；这不是对此类市场存在超额收益的声明。

先用 1–2 个工作日调查实际可用市场。目标 10–20 个事件组，最多 40 个二元合约；每组人工配置 1–3 个官方来源。若首选领域合格事件不足，先提交样本不足结论；可在新实验版本中切换到正式审批／任命事件，不能为凑样本自动扩展到全市场。

准入：交易状态正常、明确 YES/NO token、结算条件可枚举、来源可合法稳定访问、预计 30 天内有更新或结算、最小订单可适配 $10 规模。绑定 event_group_id 合并同一底层事实的风险。初始人工审核规则与来源；未来新增市场仅前向生效。

排除：体育实时竞猜、5 分钟 crypto、组合／负风险转换、杠杆、跨平台套利、社交媒体传闻、需登录或绕过访问限制的来源、浏览器自动抓取、规则严重歧义的市场。一般公开 API 可采集的数据仍不意味着所有市场都符合实验条件。

V1 输出：候选与拒绝理由、三组对照模拟账户、盘口及证据时间线、日报、离线回放。没有消息推送、复杂前端、多用户、支付功能或实盘执行。

## 3. 实验策略（在观察期前冻结）

### 3.1 三个独立实验组

每组独立虚拟现金 $1,000，结果不能相加成一个账户。共用证据／行情，但使用各自决策完成时间：

- A：事件模板中的确定性规则（明确关键词、主体匹配、否定条件、结构化字段）。不是永远不交易的弱基线。规则只允许使用决策前可见信息。
- B：Jev 直接预测最终 YES 概率。不给当前市场价格；保留原始概率、模型版本和完整输入。仅探索，不声称已校准。
- C：Jev 逐条判断证据条件，代码形成 SUPPORTS_YES / SUPPORTS_NO / INSUFFICIENT / AMBIGUOUS；只在规则支持足够明确且与 B 概率方向一致时使用 B 的原始概率产生候选。

C 对 A 的优势不能仅凭收益差判断：A 是规则策略，C 还使用了概率估计。B 对 C 的比较隔离“证据过滤”的增量；另做同一批候选的规则与 Jev 人工标签准确率比较。报告每组自己的延迟差异。

确认型 A 不伪造模型概率：人工配置与 C 相同的固定最高买价上限（初始 0.90）产生候选。C 也受该上限约束；A/C 的价格、费用、资金与退出设置相同。概率策略 B 同样限制到 0.10–0.90，避免极端高胜率交易主导首轮研究。

### 3.2 原始概率策略的候选条件

B、C 对 YES 使用 q=p_raw，对 NO 使用 q=1-p_raw。基于当前深度估计每份全部买入成本 c，要求 q-c >= 0.08；这是预先固定的探索阈值，不是统计置信下界或已证实的安全边际。不得把 C 的“证据判断自信”转换成 0.99 的结算概率。

只选择预期差额较大的一侧；平局跳过。每事件组同时最多一个方向、一笔持仓。不加仓、不买另一侧假装平仓、不裸卖空。重复新闻不重复开仓。退出后只有新的独立证据且 24 小时冷却结束才可再次候选。

这些阈值可能不合适，但只能通过新版本前向调整；不能优化到本轮历史利润最高再把它当原始成绩。A 的固定价格策略与 B/C 概率策略应分别解释，不用一张收益排名推断 Jev 的因果效果。

### 3.3 证据判断

判断正确主体、行为是否已完成、范围是否匹配、明确的否定／撤回、是否有冲突。时间由提取的字段交给代码与合约时区比较；缺字段不猜。没有证据不是 NO，未发生但截止日期未到也不是 NO。

Jev 选择预先编号的证据段落；引用编号需存在，数值需有限且位于合法范围。网页文本视作不可信数据，不能改变系统指令、来源白名单、资金或工具权限。V1 模型没有工具执行权限。复杂／矛盾案例弃权；人工复核标签不回填交易决定。

### 3.4 固定退出

主策略：首次成交后 24 小时尝试全部卖出；此前若收到按同样流程产生的反向证据，提前尝试退出。单纯概率变动不触发频繁反复买卖。市场已正式结算则按实际 payout vector 记应收，不假定永远 1/0。

出口没有足够买盘时只部分卖出，余量进入 EXIT_PENDING，每 60 秒在健康盘口上重试；超过 24 小时仍未卖出不虚构清仓。数据不健康时不成交，风险仍保留。等待实际结算的头寸持续跟踪至赎回可用；V1 没有真实赎回，账本只做明确标注的模拟资金释放。

固定记录 5m / 30m / 2h / 24h 的可清算价值作为诊断；不事后选最赚钱期限。MFE/MAE 仅基于记录的可执行清算价，不是实际获得收益。结算前终止实验时，未平仓仍在报告中，不纳入已结算胜率。

## 4. 模拟成交与资本约束

### 4.1 执行模型

只模拟有价格保护的 taker IOC/FAK 语义：可成交部分成交，剩余取消。实际 API 命名实现前核实。按每档价格与数量成交，Decimal 运算；遵守 tick size、min order size 和份额精度。价格上限在决策时固定，不能用后续有利价格回改。

基础情景：决策后增加 2 秒执行延迟，只使用模拟到达时刻之前已接收的健康盘口。并行重放 0.5 秒与 5 秒延迟，以及 50% 可用深度情景；这些是压力假设，非真实执行延迟测量。

决策时与模拟到达时分别检查价格限制、余额、费用、市场状态与深度。逐档计费并按已验证协议精度取整；不按整个订单均价近似非线性费用。官方当前文档使用 C × feeRate × p × (1-p)，实际实现读取市场配置并保留版本；字段不支持或未知则跳过，不能默认免费。

买卖盘口已经包含价差，逐档成交已经包含深度价格影响；不得再重复扣同一笔 spread/slippage。返利基础情景计为零。交易模拟不声称能完全预测隐藏流动性、同时撤单或真实匹配先后。

同一实验账户不能多次使用同一快照同一份深度。维护模拟消耗量，并保守地只在有新完整快照／明确新流动性状态后更新容量。实验组之间为相互独立的反事实账户，不互相竞争。成交状态与现金变更同一数据库事务提交。

### 4.2 默认预算（试验参数）

每笔含费用最多 $10；每事件组成本与承诺资金合计最多 $20；每组账户所有持仓成本加待成交买单承诺不超过 $100。入场不使用模型概率作 Kelly 仓位。不得借款、复用未到账赎回资金或浮盈。

累计保守净值亏损达到 $50 时该实验组暂停新增风险，继续退出和记录。无法可靠估值时不把缺失值当零波动，暂停新增风险。暂停不是损失保证，现有仓位可继续恶化。

运行费建议独立上限 $30 / 14 天，属于项目预算而非报价。实现前核实 Jev 账户计价；无法核实则仅采集或设显式请求硬上限，不宣称自动美元限额有效。每次请求预留成本、计入失败和重试，日总量上限初始 500 次、并发 2；达到上限暂停模型调用并显示覆盖损失，不影响账本与行情。初始并发与请求数需根据实际配额下调。

## 5. 数据时间与可靠性

记录 source_published_at（可空）、source_updated_at、first_seen_at、fetch_start/end、model_start/end、decision_at、sim_arrival_at、market_timestamp、local_received_at。源发布时间不精确时保留精度；不得用它证明我们尚未看到的机会。

所有存储时间为 UTC，耗时用单调时钟，报告时区可配置。时钟偏差检测失败或显著漂移时暂停延迟敏感模拟。排序使用本地可用时间加本地递增序号；来源旧时间不能让回放提前获得证据。

公共行情：初始快照后应用文档定义的增量；不假定供应商存在全局 sequence。断线、消息解析失败、乱序无法判定、积压超过阈值时使盘口失效，重新订阅／获取快照恢复；记录缺口，不补造历史。

健康度包括连接心跳、消费滞后、最近快照验证，而不只看最后一次价格变化（安静市场可以长期无变化）。每 60 秒校验快照；模拟下单前要求最近 10 秒内有验证快照或可靠 book 更新，否则刷新并推迟执行时刻。这些参数均配置化，不能把刷新后的快照倒填到过去。

证据源：仅白名单 RSS/Atom、JSON、静态 HTML 适配器。普通轮询初始 60 秒，已知发布窗口可在来源允许的频率内到 10 秒。记录 polling_delay；如果优势只持续 3 秒，60 秒轮询路线明确不适用，不用零延迟假设掩盖。

支持 ETag/Last-Modified、内容 hash、指数退避与 jitter、429 Retry-After。首次采集仅建基线；不把旧存量文档当新新闻触发交易。相同事件不同 URL 的转载进行分组；网页修改另存新版本。

## 6. 技术架构

选择 Python 3.12 + uv；原因是异步采集、统计分析、回放测试可在同一语言完成。单机、单常驻 worker，另一个只读 report CLI，不使用 Redis/Kafka/Kubernetes。

依赖候选：官方 polymarket-client 的 AsyncPublicClient（只读）和 typesafe-sdk 的异步客户端；HTTPX、Pydantic、feedparser、受限 HTML 提取、Typer、Jinja2、pytest、Ruff。精确包版本与兼容性在 M0 smoke test 核实，随后提交 uv.lock。不复制旧 SDK 教程中的接口。

```text
人工 watchlist + source mappings
        ↓
公共行情采集 ──→ 原始日志 + 盘口重建
信息源采集 ──→ 版本化 evidence ──→ A/B/C 决策
                                      ↓
                            资金与质量检查
                                      ↓
                             taker paper engine
                                      ↓
                             双向账本／持仓
                                      ↓
                        HTML + Markdown + CSV 日报
```

持久化：SQLite WAL，单 writer 队列；金额用精确十进制字符串存储并由 Decimal 运算。原始行情按天 gzip JSONL，原始证据本地按 hash 存储，数据库保存偏移/路径及 hash。数据库保留决策相关快照、快照检查点及引用；纯 replay 不调用模型或外网。

限流队列：行情写入优先，模型任务去重并合并同组待处理项；排队时信息被修订则过期旧任务。模型不阻塞行情采集。数据库落盘失败、磁盘不足或队列溢出则停止新模拟交易，报告不健康状态。

部署：本地先运行采集冒烟，正式观察可使用持续联网的 Linux 主机和单 Docker 容器，restart unless-stopped + 持久化 volume。镜像不含密钥；报告为本地生成静态文件，不对公网提供交易管理端口。GitHub Actions 用于测试，不能用作全天候 bot 宿主。主机休眠造成的缺口必须计入覆盖率。

### 6.2 最少数据实体

- experiments：配置 hash、Git revision、起止时间、模型实际版本、提示版本、运行环境。
- market_versions：事件组、token、规则原文 hash、交易状态、费用参数、tick/min_size、可用时间。
- source_versions：URL、内容 hash、原文路径、来源时间与接收时间、来源健康状态。
- book_events/checkpoints：来源时间、本地时间、序号、快照／增量、数据缺口。
- judgments：experiment/arm、证据版本、输入 hash、响应、usage、开始结束时间、错误／弃权原因。
- paper_orders/fills：唯一意图 id、到达时间、限价、每档成交、费用版本、剩余量、拒绝原因。
- ledger_entries/positions：现金借贷方向、份额、成本、费用、应收与资金释放；不可只覆盖一个余额字段。
- labels：人工证据解释标签、审核时刻、最终 payout；与策略输入隔离。
- health_events：断流、重试、预算、时钟、磁盘和恢复事件。

唯一键 (experiment, arm, evidence_version, market, action) 防重复决策；order/fill/ledger 操作事务化。重启后先对账，再恢复待处理任务；过期候选不补成交。

## 7. 异常场景的明确行为

| 情况 | 行为 |
| --- | --- |
| Jev 超时、429、非法概率、版本意外变化 | 跳过该判断；有限重试须计入时间和费用；版本变化暂停该实验臂 |
| 证据包含指令或不相关内容 | 仅作为数据，固定问题与引用校验；无法确认则弃权 |
| 新闻撤回、更正、相互冲突 | 保留原版本与原交易；新证据重新判断；冲突暂停新开仓 |
| 来源时间缺失、旧文重发 | 以首次接收时间为准；不伪造发布延迟；去重 |
| 规则变更、截止日期延期 | 新建版本，冻结新开仓等待人工复核；旧仓仍跟踪，人工处理另列 |
| 费用或 token 映射未知 | 不模拟交易，不默认零费用或 YES token 顺序 |
| 深度不足、价格越过限价 | 部分成交或拒绝，现金仅扣真实模拟成交部分 |
| 市场停止接受订单 | 停止成交；持仓进入等待状态 |
| 结算争议、50/50、作废 | 读取实际 payout；争议期间不当作已到账 |
| 无买盘／盘口失效 | 报告不可完整清算，不虚构平仓 |
| 程序崩溃／重启 | 持久化恢复、幂等对账、重新建 book，缺口不回填 |
| 同一事件多个合约同时触发 | 组级资金锁与上限，不重复使用资金 |
| 人工复核发现错误 | 加标签，原始结果不删改；新策略单独版本 |
| 14 天仍没几次机会 | 标记样本不足；不降低标准制造交易 |

## 8. 账本、报告与评估

日净盈亏 = 日末净值 - 日初净值 - 净入金 - 尚未记入账本的运行成本。运行费是共享研究成本，项目层只扣一次；单策略部署经济性另估，不能把三臂收益相加。分别报告交易损益与运营后损益。

同时展示：已实现、未实现变化、现金、成本、应收结算、费用、可清算价值、不可清算份额、按事件的风险、数据覆盖率。用买盘深度及退出费用估值，不用模型估值。无报价份额提供保守零值下界与最后有效估值（标时间），不把下界损失混成实际已实现损失，也不隐瞒未知估值。

所有候选均有漏斗：发现→有新证据→有效判断→通过阈值→到达时仍可执行→成交→退出/未平仓。报告未成交及拒绝原因。

以事件组而非模型调用为独立单元统计。人工解释准确率与最终预测准确率分开。Brier/calibration 仅对适用的二元已结算样本计算；50/50 特殊结算单列。报告样本量与事件集中度；有足够事件才做事件组聚类 bootstrap，不用虚假精确显著性。

报告去掉最大赢家、费用后、延迟增加、深度减半、剩余库存保守估值的结果。对不活跃事件与未结算事件持续追踪，避免只保留容易完成的赢家。

## 9. 验收、进度与最终决策

工程验收与策略验收分开。工程通过不代表可盈利。

工程：合成数据端到端无需密钥可回放；同一日志和版本重复运行得到相同订单／账本；崩溃恢复无重复成交；时间、金额、费用、断流、部分成交、结算边界测试通过；24 小时采集冒烟完成且缺口可审计；无任何实盘接口。

策略：7–14 个有效观察日后检查；少于 20 个独立相关证据事件，只作描述性观察，不用于自动放行实盘。即使达到 20 个也不足以证明盈利。检查净收益是否依赖一笔、压力情景是否崩溃、Jev 是否有增益和误判损失、机会金额是否覆盖运行成本。

若只有零延迟/乐观成交盈利，否决当前版本；若规则一样好，移除 Jev；若机会不足，延长或新版本换领域；若多个独立事件、保守假设下表现值得继续，提出 $50–100 小额执行验证方案，由用户另行决定实盘启用。后续 $200–300、$1,000 都是新阶段，不是自动升级。

估计实施工作量 5–8 个开发日，取决于信息源可用性和 SDK 验证；之后才开始计观察窗口。该估算不是已经启动的交付承诺。
