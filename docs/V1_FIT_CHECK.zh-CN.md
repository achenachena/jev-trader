# 当前 V1：适配性验证，而非交易系统

更新：2026-09-24。本文取代旧 V1 的立即实施范围；旧影子交易文档保留为后续候选设计。

## 当前完成

- [首批 10 个历史阅读案例](../research/pilot-001/README.zh-CN.md)：真实规则与一手来源、短引文、候选标签。
- 模型输入与标签分离的 JSON 结构。
- 无依赖的校验／导出脚本。

## 下一步（未运行）

1. 对同一冻结输入比较通用规则、Jev 和通用模型；记录版本、准确率、弃权、错误类型、延迟与成本。需要可用 API 凭据与实际价格，不上传凭据。
2. 第一轮标签为助手提出、来源核对，不能当独立金标准。模型分歧需复核；用户无需承担整批资料收集。
3. 若值得继续，再选择 3–5 个有稳定来源的活跃事件，记录消息与盘口。先看机会是否存在，不接钱包。

## 不在本轮范围

完整 paper 账户、自动下单、收益排名、maker 模拟、全天新闻抓取、历史延迟推断、扩大本金。

## 通过条件

小样本只能暴露明显错误和判断任务是否可定义，不支持统计上的盈利或能力结论。若规则足够好，不必使用 Jev；若有理解优势但没有可执行机会，不建设交易 bot。真正决定后续范围的是实验结果，而不是仓库已经写了多少设计。
